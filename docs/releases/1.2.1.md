# NekoPcbEmulator 1.2.1

Fixes for programs that drive the emulator unattended, and a rewritten guide for them. Both wire
protocols are unchanged: PCB-A stays at ASCII/1.1 and PCB-B at version 1.

## Fixes

- **Startup through `--power` no longer opens a dialog.** A board that cannot power on, for
  example because its port is busy, used to hold back the boards after it until someone clicked
  OK. Every requested board is now tried, and each failure goes to the traffic log and to standard
  error as `PCB-A: power on failed: <reason>`. Manual POWER ON keeps its dialog.
- **`--no-main` reports a failed startup.** If any requested board fails, the boards that came up
  are closed and the process exits with code 2. Without `--no-main`, the launcher stays open.
- **The 8th named pipe client is served.** It used to connect and never get a reply. A 9th gets
  "pipe busy", and gets in once a client leaves if it waits. Aborted connections and power cycles
  no longer use up client slots.
- **Closing the last board window under `--no-main` exits cleanly.** It used to end in a stack
  overflow (`0xC00000FD`); the exit code is now 0.

## Documentation

- Add "Consumindo de outro programa" to the README: download, startup, readiness, shutdown, and
  what to know before depending on the emulator.
- Describe framing, ordering, limits, counters, and error handling in both protocol documents in
  more detail, with complete example bytes for PCB-B.
- Document `--no-main`.

## Upgrading from 1.2.0

No client changes are needed. A supervisor that waited out or killed a hung startup can also watch
for exit code 2. Default ports are unchanged: TCP 5001 and 5002, serial COM5 and COM4.

## Downloads

- **Self-contained:** includes the .NET runtime; no separate runtime installation is needed.
- **Framework-dependent:** smaller package; requires the .NET 10 Desktop Runtime.

Both Windows x64 ZIP packages include the emulator, reference test client, README, protocol
documents, version, and source commit. `SHA256SUMS.txt` contains archive checksums.

## Validation

CI builds with warnings treated as errors, runs 47 isolated protocol scenarios and 6 named pipe
scenarios, then tests 38 wire-level and 5 startup scenarios against each packaged application and
checks both reference clients start. CI uses loopback TCP and named pipes. Both protocols were also
run over com0com virtual serial pairs before this release.
