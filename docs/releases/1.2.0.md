# NekoPcbEmulator 1.2.0

PCB-A now carries a 4x4 grid of 16 RGBA indicators, and each one can turn itself off after
a time chosen in the command. The PCB-A protocol moves to ASCII/1.1. PCB-B is unchanged on
the wire.

## Protocol: PCB-A ASCII/1.1

```
LIGHT[<IDX:int>] <RGBA:int> <STATE:bool>[ <MS:int>];
```

- `IDX` covers `0..15`, row-major with the origin top-left: `index = row * 4 + column`.
- `MS` is optional, `0..65535` milliseconds, the same range as PCB-B. Omitted or `0` holds
  the LED on, exactly as before.
- Expiry opens the switch and keeps the stored colour. It sends no message: every request
  still gets exactly one reply.
- Each accepted `LIGHT` replaces the previous one on that LED. Sending `MS` again restarts
  the countdown; omitting it cancels the countdown. A rejected command changes nothing.
- A duration outside the range answers `ERR RANGE`. A duration above 0 together with
  `STATE false` answers `ERR BAD_ARGS`.

See `docs/protocol-a.md` for argument rules, validation order, timing guarantees, and the
version history.

## Upgrading from 1.1.0

Two-argument `LIGHT` statements work unchanged. Clients that check any of the following need
a small update:

| What | 1.1.0 | 1.2.0 |
|------|-------|-------|
| `SYS ID` version | `ASCII/1.0` | `ASCII/1.1` |
| `SYS ID` indicator count | `LIGHTS=3` | `LIGHTS=16` |
| `LIGHT[3]` to `LIGHT[15]` | `ERR RANGE` | `OK` |
| Index range in the error detail | `outside 0..2` | `outside 0..15` |
| A third `LIGHT` argument | `ERR BAD_ARGS` | the auto-off time |

## Changes

- Show a countdown ring on timed PCB-A indicators, as on PCB-B.
- Add an auto-off field to the `LIGHT` command dialog.
- Widen the PCB-A board for the grid, and move the memory slot readout beside the pixel panel
  so it no longer runs past the board edge.
- Account for the window frame when placing board windows, so they stay on screen.
- Light the whole grid with staggered durations in the reference client demo.

## Downloads

- **Self-contained:** includes the .NET runtime; no separate runtime installation is needed.
- **Framework-dependent:** smaller package; requires the .NET 10 Desktop Runtime.

Both Windows x64 ZIP packages include the emulator, reference test client, README, protocol
documents, version, and source commit. `SHA256SUMS.txt` contains archive checksums.

## Validation

CI builds with warnings treated as errors, runs 47 isolated protocol scenarios, then tests
38 wire-level scenarios against each packaged application and checks both reference clients
start. Validation uses loopback TCP; serial transport is unchanged and was not retested for
this release.
